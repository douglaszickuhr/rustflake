# Table View, Plan 1 (dbt + Definition + dbt section) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Snowflake table tabs gain a header plus the **Data | Definition | dbt** sections. A local dbt clone (manifest, run_results, git) is configured per connection in a tabbed connection dialog.

**Architecture:**
- **Core:**
  - `rb-core/src/dbt.rs`: manifest/run_results/git parsing, the relation index, and `dbt parse`.
  - `rb-core/src/table_info.rs`: SQL builders and parsers for the header facts, columns, tags and policies, plus the merge into definition rows. Both modules are pure and tested.
- **App:**
  - `rb-app/src/dbt_store.rs`: one entity per open Snowflake connection that loads the manifest in the background and refreshes it on demand.
  - `table_tab.rs` gets the header and sections. Definition and dbt rendering live in `rb-app/src/table_sections.rs`.
  - `conn_dialog.rs` gets General / Authentication / dbt tabs.

**Spec:** `docs/superpowers/specs/2026-10-16-table-view-design.md` (sections 1, 2, Errors, Tests); visual reference boards 7, 9, 10.

## Global Constraints

- **Don't commit.**
- Comments are in Portuguese, short, and say why.
- rb-app tests use `#[::core::prelude::v1::test]`.
- All UI text goes in `app.toml` (en/pt/es).
- No new crates. `serde_json` is already in rb-core; date math uses `user_view::parse_ts`/`span`.
- Read-only toward Snowflake and the repo.
- `dbt parse` is the only process we run, plus `git` and `open`.
- Identifiers use `quote_ident`, literals use `sql_str`.
- Each section and panel fails on its own.

## Review Focus

1. Manifest `relation_name` values are quoted or lowercase (`"SALES_PROD"."MART_CRM"."X"`, `sales_prod.mart_aws.x`): the match must still work.
2. A huge manifest (tens of MB): parsing runs off the UI thread, and only the fields we use are deserialized.
3. `dbt` is missing from the PATH, or the parse hangs: show a clear message, enforce the 120 s timeout, and never freeze the UI.
4. A column exists in Snowflake but not in dbt, or the other way round: Snowflake columns drive the table; dbt-only columns are ignored.
5. A table outside the configured database (another db): the `INFORMATION_SCHEMA` calls use the table's own database.

### Task 1: `dbt.rs` (config, manifest, run_results, git)

**Interfaces:**
- **Config:**
  - `config::DbtConfig { project_dir: String, target: String }`
  - `SnowflakeConfig.dbt: Option<DbtConfig>` (serde default, skip if None)
- **Types:**
  - `pub struct Manifest { pub nodes: HashMap<String, Node>, pub child_map: HashMap<String, Vec<String>>, pub parent_map: HashMap<String, Vec<String>>, pub tests: Vec<TestDef>, by_relation: HashMap<String, String> }`
  - `pub struct Node { unique_id, name, resource_type, relation: Option<String>, file: String, fqn: Vec<String>, description, columns: Vec<(String, String)> /*name, desc*/, materialized: Option<String>, strategy: Option<String>, unique_key: Vec<String>, tags: Vec<String>, meta: Vec<(String,String)>, owner: Option<String>, raw_code: String, compiled_code: Option<String>, source_name: Option<String> }`
  - `pub struct TestDef { unique_id, kind: String /*not_null…*/, attached: String /*unique_id*/, column: Option<String>, detail: Option<String> /*"ACCOUNT_ID → stg_x" / "6 values"*/ }`
- **Functions:**
  - `pub fn parse_manifest(json: &str) -> Result<Manifest, DbError>`
  - `pub fn norm_relation(s: &str) -> String`: strip quotes, uppercase.
  - `impl Manifest { pub fn by_table(&self, db, schema, name) -> Option<&Node>; pub fn tests_of(&self, uid) -> Vec<&TestDef>; pub fn layer(&self, uid) -> String }`
  - `pub fn parse_run_results(json, target: &str) -> HashMap<String, (String /*status*/, String /*completed_at*/)>`: empty when the target doesn't match or can't be confirmed.
  - `pub fn github_url(remote: &str) -> Option<String>` (SSH, HTTPS and ssh://, with `.git` stripped)
  - `pub struct GitInfo { repo: Option<String>, branch, sha }`
  - `pub fn git_info(dir) -> GitInfo` (runs `git`)
  - `pub fn file_url(g: &GitInfo, file) -> Option<String>`
  - `pub struct DbtProject { manifest: Manifest, results: HashMap<..>, git: GitInfo, parsed_at: Option<SystemTime> }`
  - `pub fn load(cfg: &DbtConfig) -> Result<DbtProject, DbError>`: reads `target/manifest.json`; an error when it's missing.
  - `pub fn refresh(cfg) -> Result<(), DbError>`: `dbt parse --target t` with a 120 s timeout. The error carries the output. If dbt isn't found, return the message key `err.dbt_not_found`.

- [ ] **Step 1: Failing tests.** Use a fixture manifest (an inline JSON string with one model, one source, one seed, tests not_null/unique/accepted_values/relationships, a `child_map`, quoted relation names) and cover:
  - relation lookup with mixed case and quotes;
  - owner from `meta.owner`, falling back to `config.meta.owner`;
  - layer from `fqn[1]` (`["proj","staging","aws","stg"]` → "Staging"); sources and seeds give "Sources";
  - tests grouped per column, with the relationships detail `ACCOUNT_ID → stg_aws__accounts` and the accepted_values detail `6 values`;
  - `run_results` status keyed by unique_id, empty when the target differs;
  - `github_url` for `git@github.com:org/repo.git` and `https://github.com/org/repo` → `https://github.com/org/repo`;
  - `parse_manifest("{")` is an error.
- [ ] **Step 2:** Run them and confirm they FAIL.
- [ ] **Step 3:** Implement with serde structs that use `#[serde(default)]` and only the fields we need.
- [ ] **Step 4:** Run `cargo test -p rb-core --lib dbt` and confirm they PASS.

### Task 2: `table_info.rs` (header, columns, tags, policies, merge)

**Interfaces:**
- **Header facts:**
  - `pub fn facts_sql(db, schema, table) -> String`: `select table_type, row_count, bytes, last_altered, comment from <db>.information_schema.tables where table_schema = '<s>' and table_name = '<t>'`
  - `pub struct Facts { kind, rows: Option<u64>, bytes: Option<u64>, last_altered: Option<String>, comment: Option<String> }`
  - `pub fn parse_facts`
- **Columns:**
  - `pub fn columns_sql(db, schema, table)`: `select column_name, data_type, is_nullable, column_default, comment from <db>.information_schema.columns where … order by ordinal_position`
  - `pub struct ColInfo { name, kind, nullable: bool, default, comment }`
  - `pub fn parse_columns`
- **Tags:**
  - `pub fn tags_sql(db, schema, table)`: `select column_name, tag_name, tag_value, tag_database, tag_schema from table(<db>.information_schema.tag_references_all_columns('<db.s.t>', 'table'))`
  - `pub fn parse_class_tags(names, rows) -> HashMap<String /*col*/, (u8 /*level*/, String /*tag fq*/)>`: only `DATA_CLASSIFICATION`, with the level from `masking::tag_level`.
- **Policies:**
  - `pub fn policies_sql(db, schema, table)`: `select ref_column_name, policy_name, policy_db, policy_schema, policy_kind from table(<db>.information_schema.policy_references(ref_entity_name => '<db.s.t>', ref_entity_domain => 'table'))`
  - `pub fn parse_masking(names, rows) -> HashMap<String, String /*policy fq*/>`: only `MASKING_POLICY`. Tag-based policies show here too, with ref_column_name set.
- **Merge:**
  - `pub enum DescSource { Dbt, Comment, None }`
  - `pub struct DefRow { col: ColInfo, desc: Option<String>, source: DescSource, level: Option<u8>, masked_by: Option<String>, tests: Vec<String> }`
  - `pub fn merge(cols, dbt_cols: &[(String,String)], tags, masking, tests_by_col: &HashMap<String, Vec<String>>) -> Vec<DefRow>`: case-insensitive column match, dbt description preferred, a blank dbt description falls back to the comment.
  - `pub struct Summary { columns, classified, tests, undocumented }`
  - `pub fn summary(rows) -> Summary`
- **Column lineage:**
  - `pub fn column_lineage_sql(fq_col) -> String`: `GET_LINEAGE(... 'COLUMN','UPSTREAM',5)`
  - `pub fn parse_column_lineage(names, rows) -> Vec<LinNode { db, schema, object, column, distance }>`: ordered from the farthest to the nearest, deduplicated, self-edges removed.

- [ ] **Step 1: Failing tests:**
  - the SQL builders quote and escape;
  - the facts parse;
  - the merge picks the description source correctly, matches case-insensitively, and ignores dbt-only columns;
  - the summary counts;
  - the tag parse ignores other tags;
  - masking keeps only masking policies;
  - the column lineage order, with the dedup.
- [ ] **Steps 2–4:** RED, then implement, then GREEN.

### Task 3: tabbed connection dialog + dbt tab

- [ ] **Tabs:** `conn_dialog.rs` gets `General | Authentication | dbt`, a `TabBar` at the top of the form, and a field `tab: Rc<Cell<usize>>`.
  - General: kind, name, environment, plus host, port, database (Postgres) or account, database, schema, warehouse, role (Snowflake).
  - Authentication: user, password, SSL and SSH (Postgres) or user, auth method, key or PAT (Snowflake).
  - dbt: Snowflake only.
- [ ] **dbt tab:**
  - **Fields:** the project folder (with **Choose…** via `cx.prompt_for_paths` with directories enabled, the same way `key_field` uses the picker) and the target (default "prod").
  - **Status card:** loads `dbt::load` in the background when the tab opens with a folder set, and shows:
    - "Manifest found · parsed N ago" with the counts (models, sources, seeds), or "No manifest.json yet";
    - the GitHub repo and branch;
    - a **Refresh dbt** button that runs `dbt::refresh` then reloads, and shows a red error box with the output and **Copy output** on failure;
    - the note about `dbt parse`.
- [ ] **Save:** `dbt: Some(DbtConfig{..})` when the folder isn't empty, otherwise `None`. `save_connection` keeps the `dbt` from the dialog (unlike `db_filter`, which is preserved from the old config).
- [ ] **i18n.** Then `cargo build -p rb-app` and the tests.

### Task 4: dbt store + table tab header/sections

- [ ] **`dbt_store.rs`:**
  - `DbtStore { project: Load<Arc<DbtProject>> /* or NotConfigured */, refreshing: bool, error: Option<String> }` with `load(cfg)` and `refresh(cfg)` running on `cx.background_spawn`.
  - `Open` (workspace) gets `dbt: Option<Entity<DbtStore>>` for Snowflake connections. Created on connect when `cfg.snowflake.dbt` is set; reloaded when a connection is saved.
- [ ] **`TableTab`:**
  - **Sections:** `section: Section {Data, Definition, Dbt}`. Only Snowflake shows the section bar; Postgres stays as today.
  - **Header (Snowflake):** name, `DB.SCHEMA`, a dbt badge (materialization), owner, tags, and **Query** (opens a SQL tab with `select * from <fq> limit 100` via a `Workspace` callback). The facts line comes from `table_info::facts_sql`, loaded once.
  - **Definition:** columns, tags and policies loaded on first open (one task, three queries on the tab session), merged with the dbt node columns and tests:
    - a summary line;
    - a table: column, type, description with its source tag, classification chip plus a lock, test chips;
    - selecting a row opens the side panel: type, nullable, default; the description plus the Snowflake comment; protection; "Comes from" (column lineage, loaded on select, with kind dots: dbt model / source / seed / outside dbt via `by_table` on each node); tests with their status from `run_results`.
  - **dbt section:**
    - **left:** description, materialization and strategy, unique key, owner, meta, tags, tests grouped by type, and the manifest footer with Refresh;
    - **right:** file path, a Source/Compiled toggle (Compiled disabled without `compiled_code`), **Open on GitHub** (`cx.open_url`), **Open in editor** (`open <dir>/<file>`), a read-only SQL `Editor` (language sql), and the footer `branch @ sha`;
    - **states:** not configured (a "Set up dbt…" button opens the connection dialog), no manifest (Refresh), not a model ("This table isn't a dbt model in this project").
- [ ] **i18n**, then build, the tests and a release build. Then ask the user to check by hand: a mart table, the three sections, Refresh, GitHub/editor, the states.
