# rustbeaver — vários idiomas (pt / en / es)

Data: 2026-10-15
Status: aprovado em conversa, aguardando revisão da spec

## 1. Objetivo

A interface e as mensagens de erro do app em português, inglês ou espanhol. O padrão segue o
idioma do macOS; um seletor na barra lateral troca na hora, sem reiniciar.

**Sucesso** = com o macOS em inglês o app abre em inglês; escolher "Español" no seletor troca
a barra lateral, a árvore, as abas e os diálogos imediatamente, e a escolha vale no próximo
início.

### Escopo

Dentro:
- Todos os textos do `rb-app` (≈200) e as mensagens montadas pelo `rb-core` (≈25)
- Seletor de idioma, `settings.toml`, detecção do idioma do sistema
- Troca ao vivo, incluindo os widgets do `gpui-component` (que usam o mesmo `rust-i18n`)

Fora:
- Mensagens vindas do servidor (Postgres, Snowflake): ficam como o servidor manda
- Comentários e nomes no código, logs (`tracing`): continuam em português
- Formatos de número e data por região; outros idiomas além dos três

## 2. Dependências

- `rust-i18n = "4.2"` em `rb-core` e `rb-app`, e `sys-locale = "0.3"` em `rb-app`. As duas já
  estão no `Cargo.lock` via `gpui-component`: nada novo para baixar.
- O idioma do `rust-i18n` é global no processo: um `rust_i18n::set_locale` muda os nossos
  textos e os do `gpui-component` (que cai para `en` quando não tem pt/es).

## 3. Arquivos de tradução

Um por crate, em TOML (formato v2 do `rust-i18n`), uma chave por mensagem com os três idiomas
juntos:

```toml
# crates/rb-app/locales/app.toml
_version = 2

[tree.loading]
en = "loading…"
pt = "carregando…"
es = "cargando…"

[grid.rows]
en = "%{n} row(s)"
pt = "%{n} linha(s)"
es = "%{n} fila(s)"
```

- `rust_i18n::i18n!("locales", fallback = "en");` em `rb-core/src/lib.rs` e `rb-app/src/main.rs`.
- Uso: `t!("tree.loading")`, `t!("grid.rows", n = rows)`.
- Chaves por área: `conn.*` (diálogo de conexão), `sidebar.*`, `tree.*`, `sql.*`, `table.*`,
  `grid.*`, `filter.*`, `quick.*`, `lang.*`, e no core `err.*`.
- O português atual vira o texto `pt` sem mudanças; `en` e `es` são traduções novas.

## 4. Idioma ativo

```rust
// rb-core/src/config.rs (junto do resto da config em disco)
pub enum Language { Auto, Pt, En, Es }      // serde: "auto", "pt", "en", "es"; padrão Auto
pub struct Settings { pub language: Language }
pub fn settings_path() -> PathBuf; pub fn load_settings() -> Settings; pub fn save_settings(&Settings)

// rb-app/src/lang.rs
pub fn resolve(choice: Language, os: Option<&str>) -> &'static str   // "pt" | "en" | "es"
pub struct Lang(pub Language);              // Global do gpui
pub fn set(choice: Language, cx: &mut App)  // set_locale + set_global + salva settings.toml
```

- `resolve(Auto, os)`: `pt*` → `pt`, `es*` → `es`, qualquer outro ou `None` → `en`. Com escolha
  explícita, ela vence. `os` vem de `sys_locale::get_locale()` (ex.: `pt-BR`, `en-US`).
- Início (`main`): lê `settings.toml`, `resolve`, `set_locale`, `set_global(Lang)` antes de abrir
  a janela.

### `settings.toml`

Em `app_dir()` (ao lado de `connections.toml`), lido e gravado por `rb-core::config` com o
mesmo `save` atômico:

```toml
language = "auto"   # auto | pt | en | es
```

Arquivo ausente ou inválido = `auto`, sem erro para o usuário (só `tracing::warn`).

## 5. Troca ao vivo

`lang::set` faz `set_locale`, `cx.set_global(Lang(..))` e `cx.refresh_windows()`.

- Tudo que é texto montado no `render` troca no próximo quadro.
- Textos guardados em estado:
  - Itens da árvore (`TreeItem` com "carregando…", "Tabelas (n)"): `SchemaTree` observa o
    global (`cx.observe_global::<Lang>`) e chama `rebuild`.
  - Placeholders de `InputState` criados uma vez (filtro WHERE da aba de tabela): a view
    observa o global e chama `set_placeholder`.
  - Linhas de status (`"12 ms"`, `"erro"`) e notificações já na tela: trocam quando forem
    substituídas. Aceito: não vale guardar chaves no estado só para isso.
- Mensagens do `rb-core` (`DbError`) são montadas com `t!` na hora do erro, no idioma daquele
  momento.

## 6. Seletor

- Linha fixa no pé da barra lateral: `🌐 Auto (Português)` / `🌐 English`, no mesmo estilo
  `side_item` das linhas WH/Role.
- Clique: diálogo com quatro opções (Auto, Português, English, Español), a atual marcada com ✓.
  Escolher fecha o diálogo e chama `lang::set`.
- Os nomes dos idiomas aparecem sempre na própria língua (não são traduzidos).

## 7. Testes

- `lang::resolve`: `pt-BR`/`pt-PT` → pt, `es-MX` → es, `en-GB`/`de-DE`/`None` → en, escolha
  explícita vence o sistema.
- `settings.toml`: ida e volta; ausente e inválido → `Auto`.
- Completude: para os dois `locales/app.toml`, toda chave tem `en`, `pt` e `es` não vazios
  (lê com o crate `toml`, que já é dependência).
- Chaves usadas existem: teste que varre `src/**/*.rs` atrás de `t!("…")` e confere cada chave no
  arquivo do crate (o `rust-i18n` não reclama de chave ausente: mostraria a própria chave).
- Manual: macOS em inglês abre em inglês; trocar para Español com a árvore expandida e uma
  aba de tabela aberta; reiniciar e conferir que a escolha ficou.

## 8. Ordem sugerida
